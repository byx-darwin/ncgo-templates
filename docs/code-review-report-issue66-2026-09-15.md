## Scope

Fixes a JWT `Claims` field-mismatch bug present in `base-hertz`, `admin-bff-hertz`, and `ratelimit-hertz`: all three packages previously defined `Claims{UserID, UUID, AK, Roles}` and parsed an incoming token's `"uuid"` claim key, but the actual token issuers (`user-kitex`, reusing `rbac-kitex`'s JWT issuance) only ever sign `{uid, roles}`. Every real token therefore decoded to an empty `UUID`/`UserID`, silently degrading per-user rate limiting (`rateLimitUserUUID`), idempotency-key scoping, and — in `admin-bff-hertz` — the RBAC `Enforce` call's `Uid` argument, i.e., authorization decisions were being made against an empty identity. The fix unifies all three packages onto `Claims{Uid, AK, Roles}` (`json:"uid"`), matching `user-bff-hertz`'s pre-existing, already-correct shape, and updates every consumer (JWT middleware, idempotency middleware, rate-limit middleware, `admin-bff-hertz`'s `auth`/`current_user` handlers and `Authz` middleware) plus tests and READMEs. `ratelimit-hertz` was added as a third task (`1be9967`) after the final whole-branch review of the first two tasks found the same bug pattern there.

This branch went through extensive internal review during implementation — per-task reviews plus two rounds of final whole-branch review, with a fix-wave commit (`ebe6255`) cleaning up gofmt spacing, a stale `uuid`-named local variable, and stale doc/comment text left over from the rename. This report is the formal Phase 4 delivery record, independently re-verified against the merged diff rather than re-running the same process.
