# Plan — wf-2026-08-18-002 (Issue #5, fast mode)

**Title:** chore(ratelimit-hertz): remove manual pb.Register fallback now that ncgo #70/#71 generates per-service routers

**Issue:** https://github.com/byx-darwin/ncgo-templates/issues/5

## Problem (TDD RED — confirmed)

With the fixed ncgo (build `0d5a8df`, PR #71), `ncgo new … --kind hertz --template-dir ratelimit-hertz`
now emits a per-service router `internal/router/pb/<service>.go` defining `func Register`.
The template `internal_router_pb_middleware_go.yaml` ALSO defines a fallback `func Register` (+ `Ping`),
so package `pb` gets a duplicate → `Register redeclared in this block` → `go build ./...` fails.

## Changes

### File 1 — `ratelimit-hertz/hertz-template/internal_router_pb_middleware_go.yaml`
- Delete `func Register(r *server.Hertz)` and `func Ping(ctx, c)`.
- Delete now-unused imports: `"context"`, `"github.com/cloudwego/hertz/pkg/app/server"`,
  `pb "{{.Module}}/internal/pb"`, `"{{.Module}}/internal/pkg/response"`.
- Keep `"github.com/cloudwego/hertz/pkg/app"` (used by `rootMw`/`_pingMw` return type).
- Keep `rootMw()` and `_pingMw()`.
- Rewrite the header comment: drop the stale "loop_service overlay cannot regenerate per-service
  files for Hertz IDLs" claim; describe the file as middleware helpers only and note it now
